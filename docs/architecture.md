# ProbeMinimax boundary

User action → immutable publisher profiles → contract-side web acquisition → independent semantic outcome matrix → exact AND/OR minimax planner → stored adaptive probe policy or impossibility witness.

The contract fixes 1–4 Boolean probe predicates, positive integer policy costs, a budget and a publisher repository. A caller submits only a full-commit raw GitHub URL and SHA-256. The publisher describes 2–4 alternative API compatibility modes in prose; callers cannot submit an outcome matrix or a winning plan. External sources own the descriptions, not their veracity. No frontend or offchain processor supplies an authoritative interpretation.

Leader and validators acquire complete source bytes inside nondeterministic execution, verify the commitment and parse bounded profiles. Validators derive their own YES/NO/UNKNOWN cell for every profile/probe, including negative and absent statements. Exact answers must agree. A separate full-source audit checks substantive relevance of every leader paragraph anchor and all UNKNOWN decisions. There are no confidence tolerances.

UNKNOWN means either probe answer remains possible. It is included in BOTH successor candidate sets. A complete tree must identify a unique profile under every permitted outcome sequence. The deterministic compiler memoizes candidate-mask/unused-probe states and minimizes `probe_cost + max(yes_cost, no_cost)`. Equal costs prefer constructor probe order. Positive-cost probes with a no-progress branch cannot improve the worst case and are pruned. Some UNKNOWN cells are harmless; others make full identification impossible.

READY stores a complete policy within budget. COST_LIMIT stores the optimal policy but does not permit traversal through `walk`. AMBIGUOUS stores two profiles and a complete shared answer sequence that no available probe can separate. Profiles are never removed merely because their behavior is unspecified.

`walk` is a read-only interpreter of HYPOTHETICAL answers. It does not acquire actual probe results, execute a test, attest a diagnosis, or certify service delivery. A leaf identifies a candidate relative to the closed catalogue and the published expected behaviors. An implementation outside the catalogue can still reach a leaf. Costs are configured policy units, not measured latency or GEN.

State contains immutable configuration, append-only compiled batches, complete normalized profile texts, matrices, source bindings and trees/witnesses. Hash replay and eight batches bound lifetime storage; permissionless callers can exhaust the cap using distinct valid publisher records. There is no owner override, graph proposal, mutable version transition, certificate or settlement. The algorithm is established minimax decision-tree planning; the contract contribution is consensus-derived ternary semantics coupled to robust planning and auditable onchain traversal.

Limits: 4 profiles, 4 probes, 8 paragraphs/profile, 400 characters/paragraph, 16,000 source bytes, positive probe costs up to 100, budget up to 400, and 8 accepted batches. Unsupported/ambiguous prose becomes UNKNOWN. Transport, commitment, schema or model-format failures revert instead of producing accepted plans. Exact semantic agreement may fail or share a model error. Public source hashes authenticate bytes, not authorship or real system behavior. Fixtures are synthetic.
